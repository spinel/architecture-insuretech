## Архитектурные решения

### Event-Driven взаимодействия

#### 1. Обновление тарифов страховых компаний
**Было**: Синхронные запросы каждые 15 минут
**Стало**: 
- ins-product-aggregator → Kafka Topic `insurance.products.updated`
- core-app ← Kafka Consumer (в реальном времени)
- ins-comp-settlement ← Kafka Consumer (в реальном времени)

#### 2. Создание страховок
**Было**: REST API раз в сутки
**Стало**:
- core-app → Kafka Topic `insurance.policies.created`
- ins-comp-settlement ← Kafka Consumer (в реальном времени)

#### 3. Взаиморасчёты со страховыми компаниями
**Было**: Синхронные запросы
**Стало**:
- ins-comp-settlement → Kafka Topic `insurance.settlements.required`
- Settlement Processor ← Kafka Consumer
- Settlement Processor → страховые компании (асинхронно)

### Паттерн Transactional Outbox

**Применение:**
- core-app: при создании страховок
- ins-product-aggregator: при обновлении тарифов
- ins-comp-settlement: при формировании взаиморасчётов

**Реализация:**
1. Бизнес-транзакция в основной таблице
2. Запись события в Outbox Table (в той же транзакции)
3. Outbox Publisher читает события и публикует в Kafka
4. Удаление обработанных событий из Outbox Table

### Kafka Topics

- `insurance.products.updated` - обновления тарифов
- `insurance.policies.created` - создание страховок
- `insurance.settlements.required` - требования к взаиморасчётам
- `insurance.companies.status` - статус страховых компаний

## Преимущества Event-Driven архитектуры

### 1. Масштабируемость
- Горизонтальное масштабирование каждого сервиса
- Параллельная обработка множественными консьюмерами
- Автоматическое распределение нагрузки

### 2. Отказоустойчивость
- Изоляция сбоев между сервисами
- Автоматические повторные попытки
- Dead Letter Queue для проблемных сообщений

### 3. Производительность
- Асинхронные неблокирующие операции
- Кэширование актуальных данных
- Batch обработка для эффективности

### 4. Гибкость
- Слабая связанность между сервисами
- Event Sourcing для полной истории
- Простое добавление новых интеграций

## Готовность к росту до 10 страховых компаний

### Решённые проблемы:
1. **Экспоненциальный рост времени ответа** → Асинхронная обработка
2. **Увеличение вероятности сбоев** → Изоляция и retry механизмы
3. **Рост нагрузки на инфраструктуру** → Горизонтальное масштабирование
4. **Усложнение мониторинга** → Event tracking и метрики

### Ожидаемые результаты:
- Время ответа: стабильное независимо от количества компаний
- Отказоустойчивость: сбой одной компании не влияет на другие
- Масштабируемость: линейное масштабирование при росте нагрузки
- Мониторинг: детальная видимость всех событий и операций
