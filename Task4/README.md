# Задание 4: Проектирование продажи ОСАГО

## Выполненные задачи

### ✅ 1. Анализ требований ОСАГО
- **Пользовательский путь**: Заполнение заявки → Получение предложений → Выбор предложения
- **Ключевое требование**: Real-time отображение предложений по мере поступления
- **Максимальное время ожидания**: 60 секунд на ответ от страховой компании
- **Пиковая нагрузка**: 2,500 одновременных пользователей

### ✅ 2. Проектирование osago-aggregator

#### Функциональные обязанности:
- Отправка заявок во все доступные страховые компании (параллельно)
- Периодический опрос статуса заявок
- Агрегация и передача результатов в core-app
- Управление 60-секундным таймаутом

#### Хранилище данных:
**Решение**: Требуется собственное хранилище данных

**Структура**:
- `osago_applications` - заявки ОСАГО
- `osago_offers` - предложения от страховых компаний  
- `osago_outbox` - события для публикации

### ✅ 3. API для core-app

#### REST API Endpoints:
- `POST /api/v1/osago/applications` - создание заявки
- `GET /api/v1/osago/applications/{id}` - получение статуса
- `WS /api/v1/osago/applications/{id}/stream` - real-time обновления

#### API для веб-приложения:
- `POST /api/v1/osago/quote` - создание заявки
- `GET /api/v1/osago/quotes/{id}/stream` - Server-Sent Events

### ✅ 4. Средства интеграции

#### core-app ↔ osago-aggregator:
- **REST API** - для создания заявок и получения статуса
- **WebSocket** - для real-time streaming предложений
- **Event-Driven** - через Kafka для асинхронной обработки

#### Веб-приложение ↔ core-app:
- **REST API** - для создания заявок
- **Server-Sent Events (SSE)** - для real-time обновлений

### ✅ 5. Паттерны отказоустойчивости

#### Rate Limiting:
- 100 RPS на страховую компанию
- 50 RPS от core-app к osago-aggregator
- 10 RPS от веб-приложения к core-app

#### Circuit Breaker:
- Failure threshold: 50%
- Recovery timeout: 30 секунд
- Half-open max calls: 5

#### Retry:
- Max attempts: 3
- Backoff strategy: exponential (1s, 2s, 4s)
- Retryable errors: 5xx, timeout

#### Timeout:
- osago-aggregator → страховые компании: 60 секунд
- core-app → osago-aggregator: 30 секунд
- Веб-приложение → core-app: 10 секунд

## Архитектурные решения

### Новые компоненты:
1. **osago-aggregator** - 5-10 реплик для обработки заявок
2. **OSAGO database tables** - хранение заявок и предложений
3. **WebSocket/SSE** - real-time коммуникация
4. **OSAGO-specific Kafka topics** - `osago.offers.received`

### Масштабирование:
- **osago-aggregator**: 5-10 реплик (2 CPU, 4GB RAM)
- **core-app**: увеличение до 10-15 реплик при пиковой нагрузке
- **Автоматическое масштабирование** на основе метрик

### Кэширование:
- **Redis Cache**: кэширование результатов по VIN номеру (TTL: 1 час)
- **Кэширование статуса** страховых компаний
- **Кэширование тарифов** ОСАГО

## Поток обработки заявки

### 1. Создание заявки:
```
1. Пользователь заполняет форму → Веб-приложение
2. Веб-приложение → core-app (POST /api/v1/osago/quote)
3. core-app → osago-aggregator (POST /api/v1/osago/applications)
4. osago-aggregator создает заявку в БД
5. osago-aggregator отправляет заявки во все страховые компании (параллельно)
6. Возврат quote_id пользователю
```

### 2. Обработка предложений:
```
1. osago-aggregator периодически опрашивает статус заявок
2. При получении предложения:
   - Сохранение в БД
   - Публикация события в Kafka
   - Отправка через WebSocket в core-app
3. core-app → веб-приложение (SSE)
4. Веб-приложение отображает предложение пользователю
```

### 3. Завершение заявки:
```
1. По истечении 60 секунд или получении всех ответов
2. osago-aggregator помечает заявку как completed
3. Публикация финального события
4. Уведомление пользователя о завершении
```

## Преимущества решения

### 1. Производительность:
- **Параллельная обработка** заявок во всех страховых компаниях
- **Real-time отображение** предложений
- **Кэширование** для повторных запросов

### 2. Отказоустойчивость:
- **Circuit Breaker** защищает от каскадных сбоев
- **Retry механизмы** для временных сбоев
- **Graceful degradation** при недоступности части компаний

### 3. Масштабируемость:
- **Горизонтальное масштабирование** всех компонентов
- **Автоматическое масштабирование** при пиковой нагрузке
- **Изоляция нагрузки** между пользователями

### 4. Пользовательский опыт:
- **Мгновенное отображение** предложений
- **Прозрачность процесса** обработки
- **Надежность** при высоких нагрузках
